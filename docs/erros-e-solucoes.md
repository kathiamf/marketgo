# Erros encontrados e soluções

Este registro descreve problemas observados durante a implementação. Um erro de instalação não significa que houve falha no aplicativo final. Consulte os arquivos correspondentes em `logs/` para as saídas dos comandos. Mensagens antigas são preservadas; os resultados finais são os logs `*-final.log`, `2026-10-28-tests.log`, `2026-10-28-typecheck.log`, `2026-10-28-lint.log`, `2026-10-28-expo-doctor.log` e `2026-10-28-web-export.log`.

| Problema observado                                                                                                      | Causa identificada                                                                                               | Solução aplicada e estado                                                                                                                                                                      |
| ----------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `npm install` retornou `ERESOLVE`: `react-dom@19.3.1` exigia `react@^19.3.1`, mas o projeto usa React 19.3.0.           | Versões web fora do alinhamento do Expo SDK 58.                                                                  | Instalados `react-dom` e `react-native-web` pelas versões recomendadas por `npx expo install`. Instalação concluída. A tentativa e o diagnóstico estão em `2026-10-28-dependency-install.log`. |
| Jest tentou executar `supabase/tests/db.test.mjs` como CommonJS; a sintaxe ESM (`import`/`export`) causou erro.         | O padrão de descoberta do Jest também encontrou o teste de banco, que deve rodar pelo executor nativo do Node.   | O `testMatch` do Jest foi limitado a `__tests__/**/*.test.ts`; os testes SQL rodam separadamente via `node --test`. Na execução final, passaram 37 testes de app e 13 de banco.                |
| Primeira verificação TypeScript reportou incompatibilidades nos tipos Supabase, cor de ícone e callback de atualização. | Tipos e props não correspondiam aos contratos usados pelo SDK e pelas telas.                                     | Tipos, valores e callback foram corrigidos. `npm run typecheck` passou após a correção.                                                                                                        |
| `npx expo lint` falhou após a configuração automática com versões de ESLint inconsistentes.                             | O comando de setup automático deixou uma configuração que não executava o ESLint instalado de forma consistente. | O script `lint` executa `eslint .` diretamente. `npm run lint` passou. A falha do comando Expo não é apresentada como se esse comando tivesse passado.                                         |
| Expo Doctor identificou `expo-font` ausente e `react-native` em patch incompatível com o SDK.                           | Dependências nativas e versão patch não alinhadas à matriz SDK 58.                                               | Dependências adicionadas/alinhadas por `npx expo install`; a verificação final foi 20/20.                                                                                                      |
| A tela web não inicia os fluxos de autenticação ou catálogo quando as variáveis do Supabase estão vazias.               | Este ambiente não contém `.env` nem credenciais de projeto Supabase.                                             | A tela informa a configuração necessária, sem usar backend fictício. A exportação web e a tela inicial foram verificadas; os fluxos integrados continuam pendentes de credenciais.             |

## Avisos de auditoria de dependências

Durante a instalação, o npm informou vulnerabilidades (o último resumo registrado foi 14: 11 low e 3 high). Esse aviso não identifica, por si só, a exposição ou o impacto no aplicativo; não foi executada uma auditoria detalhada, portanto não se atribui severidade por pacote neste relatório. Avalie `npm audit` em uma revisão específica antes de atualizar dependências, evitando atualizações forçadas que possam quebrar a compatibilidade do Expo SDK.

## Observações sobre os registros

- Os logs são evidências de execução, não uma afirmação de que todos os cenários do produto foram verificados.
- `npm test`, `npm run typecheck`, `npm run lint`, `npx expo-doctor` e `npx expo export --platform web` foram executados após a formatação e concluíram com sucesso.
- `npx expo start --web --port 8081` foi aberto no navegador. A mensagem observada informa que é preciso configurar `.env`.
- Os testes manuais de integração permanecem pendentes; veja [testes-manuais.md](./testes-manuais.md).
